# Codex App 接手步骤

这些操作由用户在App中完成。本地交接包不自动创建App项目或聊天。

## 1. 创建项目并关联目录

- 项目显示名称：Record Companion · 唱片桌搭。
- 主工程目录：自己克隆的record-companion仓库根目录。
- 外部参考目录：按本机实际资料配置，可选。
- 主控的工作目录选择主工程；参考库按只读约定使用。

在App中创建关联本地文件夹的项目，选择自己的仓库目录。需要外部资料时再添加参考目录；具体路径由每位协作者配置，不保存到公开仓库。

只读使用是项目工作约定，不代表App已自动对参考目录施加只读权限。

## 2. 创建总规划主控聊天

在这个项目中创建聊天，建议名称：总规划｜唱片桌搭。
沿用你自己的默认模型，以主工程目录工作。

按D047、D048，每个对话只负责一个明确部分。总规划统一首版范围、优先级、整机流程与跨功能取舍；复杂且独立的功能按需另开细规划，具体实施再单独开对话。

## 3. 直接发送这段消息

~~~text
请作为Record Companion唱片桌搭项目的总规划主控，以当前仓库根目录工作。
本对话只负责总规划；需要单功能细规划或具体实施时，提醒我新开对应部分的对话。
请先读取 README.md、AGENTS.md、docs/project-brief.md、docs/decisions.md 和 docs/controller-prompt.md，
按照完整主控提示词和当前阶段继续推进。若配置了外部参考资料库，按只读约定查阅。
~~~

也可以打开 [完整主控提示词](controller-prompt.md)，将分隔线下的正文直接发给新聊天。

## 单功能细规划与具体实现

按实际需要创建对话。细规划可以聚焦音频与存储、电池电源、墨水屏与本体交互等复杂模块；实现可以聚焦音频原型程序、电源电路、网页、PCB或结构等一个部分和阶段。简单功能在总规划收敛。

总规划先准备对应部分的已确认需求、来源、交付位置、验收条件和未决项，由用户在App中另开对话。细规划和实现分别使用下面的入口，补充具体输入；完整主控提示词用于总规划对话。

单功能细规划入口：

~~~text
请负责Record Companion项目的【功能名】细规划，以当前仓库根目录工作。
本对话只负责这一功能的详细规则、参数、候选选型、接口与原型试验/验收方案。
先读取AGENTS.md、docs/project-brief.md、docs/function-spec.md、docs/decisions.md、docs/repository-map.md
以及相关来源，工作稿按需放入docs/feature-plans/并由功能规格引用，明确已确认与待审阅项。
需要具体实现或超出本功能时提醒另开对话；跨功能和范围取舍提交总规划评审。
~~~

具体实现入口：

~~~text
请负责Record Companion项目的【具体部分与阶段】，以当前仓库根目录工作。
本对话只负责这一部分，超出范围时提醒我新开对应对话。
先读取AGENTS.md、docs/project-brief.md、docs/function-spec.md、docs/decisions.md、docs/repository-map.md、
已确认的对应细规划及工程目录README，按已确认需求推进，并记录真实交付与验证结果。
影响已确认功能、接口、体验或成本的重要变更，先提出总规划评审建议。
~~~

## 第一轮应看到什么

- 简短复述已确认的音乐唱片桌搭与挂件。
- 两种具体、可审阅的本体、挂件与操作概念，附推荐理由。
- 有针对性的材料核实、最小模块原型与通过标准。
- 实际需要的技能和来源安排。

GitHub远程仓库保存工程版本；Codex项目组织聊天与文件访问。它们分别设置，关联Git远程后仍需完成上述App步骤。
