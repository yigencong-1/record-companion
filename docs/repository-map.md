# 仓库职责与完善顺序

日期：2026-10-08。以下按本轮补齐文档后的结构说明。仓库已有项目入口、决策、验证历史、来源与概念资产，能够支撑当前功能审阅与资料协作；固件、硬件和结构还没有实际工程及构建入口，完整选型报告、实物结果和项目许可证也尚未形成。

按D048，总规划统一范围与跨功能取舍，复杂且独立的功能按需另开细规划，具体实施另开对应对话。当前已确认需求以功能规格和决策记录为准；细规划稿中的新建议经审阅后纳入，引用详细文件时同一规则只维护一份。职责与接手入口见[项目工作约定](../AGENTS.md#规划主控与对话分工)和[App接手说明](app-setup.md#单功能细规划与具体实现)。

| 目录 | 当前内容与职责 | 实现时再补的内容 |

| [hardware](../hardware/README.md) | 材料盘点和硬件交付说明；尚无原理图或PCB | 候选报告、接口及电源预算、接线、BOM、嘉立创源工程；prototype/和product/中按实际板版号保存 |

| [web](../web/README.md) | 设备管理网页的独立职责入口；尚无页面代码 | 本地/AP与局域网管理源码、实际接口契约、固件打包方式和手机端验证 |

工程目录按实际交付建立子目录；当前不预设SDK、网页框架、制造层数，也不添加尚无工程可运行的构建流水线。

## 当前优先补齐什么

| 顺序 | 交付 | 当前处理 |
|---|---|---|
| 1 | 首版功能、操作及验收计划 | 本轮新增功能规格评审稿；关键选择和整体规则尚待审阅 |
| 2 | 清晰的源码和设计归属 | 本轮补齐固件、硬件、结构、网页入口，修正贡献说明中的网页位置 |
| 3 | 已选模块的依据与接口 | 用户审阅功能后形成候选报告，记录价格来源、性能证据与接口，随后再建立真实模块工程 |
| 4 | 可复现的工程与实物验证 | 随真实实现加入依赖版本、构建/烧录/接线步骤和测试证据；当前不声称已有这些能力 |
| 5 | 正式设计和交付版本 | 按开发流程加入试验板、成品板与结构版号及制造文件，保留改版原因 |

项目自建源码与硬件设计的许可证尚待单独选择；当前公开可读不等于已选择统一复用许可。外部代码、素材和参考设计继续遵守各自许可，采用时保留原声明与来源。许可证选择不改变现有公开与Fork/PR协作要求。

在进入实际实现时，为对应工程提供真实可执行的构建/验证命令；自动检查依据届时采用的工具链和实际风险设置。
