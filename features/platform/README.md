# 主控与系统架构选型专项

首轮比较日期：2026-10-08；第二轮板型、官网芯片资料与功能资源核对：2026-10-09。按D061负责平台、计算/解码分工、准确原型板及资源建议。D063已确认：**先用ESP32-S3验证模块功能，最终设计以ESP32-S31为主**；这是两个阶段的主控安排，成品不同时安装两颗主控。用户反馈当前所查渠道买不到S31，不等于已核实所有渠道无货。本轮已完成候选硬件资源分配；测试板实际配置与引脚须按板级资料确认，S31成品模组、内存、封装与外围仍待收敛。主控选型对话本轮结束，接线、固件和实测另开实现对话。

## 首轮结论与推荐

**S3资源比较的参考基准为ESP32-S3-DevKitC-1-N8R8、PCB v1.1、ESP32-S3-WROOM-1-N8R8模组，8 MB Flash + 8 MB PSRAM；推荐由主控软件解码。** 配合主控统一管理的microSD、外置左右音频输出与既有墨水屏参考方案形成整机台架；16位I2C GPIO扩展器作为整机联调候选，最小音频模块验证不需要先安装它。此参考基准不要求模块测试必须购入该板。板卡版号与模组后缀须在接入时核对；同名兼容板、无PSRAM版本及v1.0不能直接套用本页资源表。[P1]

推荐依据是首版有适用的官方解码/存储/网络驱动，能使用统一文件与播放模型，且无需新增独立解码器。1位SDMMC、无MCLK音频、I2C RTC/NFC及慢速扩展的旧RST占位草案余3直连；若改PN7160 VEN直连则先扣1，再按灯光/运动等已选信号累计核算。共享总线仍可评估，但扩展余量须由准确板型与外围决定，不能直接承诺保留3路。

**ESP32-S31是用户指定的成品主线，后续验证台架优先核对ESP32-S31-Korvo-1 V1.1主板。** 官方指南标明16 MB Flash + 16 MB PSRAM、双声道ES8389/两路NS4150B、4位microSD，并有可复用的LCD排针。它已有ESP-IDF v6.1稳定版文档与官方音频组件的支持声明。待准确板型可购后，验证连接器复用及真实MP3、SD上传、显示、识别并发；这些条件当前尚无本项目实测。成品以S31为主不等于继续安装整块Korvo大板，也不等于已冻结N16R16V模组或板载音频链路。[P3][P4][P5][P6][P7]

S31并非S3的开发板后缀。其芯片/模组接口与外部内存余量更大，但内部共享SRAM仍为512 KB；不能用240/320 MHz的比值推算多任务能力、音质或续航。S31 Function-CoreBoard-1有29路GPIO列入排针表，其中还包含板载与启动信号，不直接等于60路扩展；其音频是单声道，需外置立体声输出，故本轮不优先推荐它作为整机扩展台架。[P2][P3][P8]

这里比较S3与S31两个阶段的平台配置；音频D064的音质与性价比两条声音路线共用一套S3主控、SD及三线I2S，不需要两套主控。独立VS1053解码仅在测得CPU解码瓶颈时作为条件变更；它不能解决SD写入长延迟，亦没有更好音质或更低整机功耗的现有证据。准确音频链路由[音频专项](../audio/README.md)联合选择。

## 官网芯片对比与功能资源草案

本轮依据乐鑫官网芯片和模组手册，不以第三方音频板作为芯片能力基准。S3芯片手册为v2.2、WROOM-1/1U为v1.8；S31芯片手册为预发布v0.5、WROOM-3/3U为预发布v0.7。旧版S3芯片手册v1.6仅作历史参考，旧板卡例程不作为当前实现依据。[P2][P15][P19][P20]

| 比较项 | ESP32-S3 | ESP32-S31 | 对当前规划的影响 |
|---|---|---|---|
| 主处理器 | 双核Xtensa LX7，最高240 MHz | 双核32位RISC-V，最高320 MHz | 都能作为软件解码候选；指令集不同，迁移需重新编译、验证组件 |
| 内部内存 | 512 KB SRAM，另有16 KB RTC SRAM | 512 KB高速SRAM，另有32 KB低功耗SRAM | 高速内部内存没有按主频增长；实时DMA、任务栈、网络仍单独预算 |
| 建议外部内存起点 | N8R8模组：8 MB Flash + 8 MB PSRAM | WROOM-3-N16R16V候选：16 MB Flash + 16 MB PSRAM | 都是配置建议；歌曲存SD，PSRAM用于缓存，不代替全部内部RAM |
| GPIO口径 | 芯片45；WROOM-1最多36，N8R8另有3脚被Octal PSRAM占用 | 芯片60；WROOM-3引出54，不含专用高速USB数据对 | 先扣内存、启动与维护；开发板只按实际排针和板载占用计算 |
| 当前需要的接口 | 2路I2S、2路I2C、2路通用SPI、SDMMC、USB、PWM/脉冲计数 | 同样有2路I2S、2路常规I2C和2路通用SPI，另有低功耗接口；SDMMC、USB、PWM/脉冲计数 | 基础功能不需启用全部外设，按下面分工保留一部分控制器余量 |
| SD接口 | SDMMC信号可经GPIO矩阵分配 | 第一卡使用GPIO20–25、第二卡使用GPIO35–40，按专用IO规划；1/4位 | S3先1位；S31成品建议预留第一卡完整4位信号，不复制S3编号 [P20][P22] |
| 网络与USB | Wi-Fi b/g/n、BLE；USB全速OTG与Serial/JTAG | Wi-Fi 6、BLE/Classic、802.15.4；USB高速OTG及Serial/JTAG | 首版使用AP/STA和有线维护；其他协议和高速USB用途尚未确定 |

**S31启动脚资料不一致**：芯片手册第36页和模组手册第18页列GPIO36、37、60、61；ESP-IDF v6.1 GPIO页将GPIO36–40、60–61均列为启动脚。规划先保留这7脚的并集，具体接线依实际硬件/SDK版本核实，不能把GPIO36当作普通空闲脚。SDMMC API页还含其他芯片的通用说明，S31总线宽度和IO以芯片手册第74/75页为依据。[P2][P20][P21]

**资源余额按平台分开算**：官方S3 N8R8 v1.1保守池24路，旧NFC RST占位草案为21直连及9慢速扩展、余3；若PN7160 MINI的VEN替代扩展器RST并改直连，则条件上22直连及8慢速扩展、余2。电源故障通知若也须直连，须在此基础再扣1，不把同一余额重复使用。S31 WROOM-3先保留启动/维护后形成43路候选池；旧推荐为32直连、余11，已包含1路NFC RST，VEN替代该路时不再重复新增。LIGHT_EN、MOTOR_FAULT、可选盘侧脉冲/CD、MCLK、额外功放EN及控件调整等按实际选择累计扣除，暖白PWM替代原灯光数据时不重复算两个输出。联合条件账本见[分配稿](resource-allocation.md#余额和改配影响)，尚未确定最终扩展器或接线。

音频缓存起步仍为192 KiB PCM + 64 KiB压缩预读 + 64 KiB上传/文件缓存，外部缓存先预算320–512 KiB；内部音频、DMA、卡驱动及任务栈先96–160 KiB，网络/界面/索引另计。1位/4位SD与缓存大小都通过播放中上传测试收敛，不承诺吞吐或全部内存余量。

候选GPIO编号已给出，下一步按屏/识别/RTC/电源模块的准确接口与上电状态核对，转为实际接线稿；进入模块实现后固定软件版本并验证音频、SD、USB恢复及上传并发。S31保留独立的板级配置，到硬件可用时重验同一功能，不要求两芯片使用相同编号。

## 两个平台的完整方案

以下外围是资源与费用口径，尚非批准BOM。读卡器、电源、音频输出和RTC不由本专项单方面冻结。

| 项目 | A：S3软件解码，当前模块验证 | B：S31软件解码，成品主线准备 |
|---|---|---|
| 主控系列 | ESP32-S3，双核Xtensa LX7，最高240 MHz，512 KB内部SRAM | ESP32-S31，双核32位RISC-V，最高320 MHz，512 KB共享SRAM；模组资料另列32 KB低功耗SRAM，不作实时音频堆使用 |
| 准确原型板 | ESP32-S3-DevKitC-1-N8R8，PCB v1.1，WROOM-1-N8R8 | ESP32-S31-Korvo-1 V1.1主板；指南为WROOM-3、16 MB Flash + 16 MB PSRAM，交货核对完整后缀；数据表对应候选为N16R16V |
| 外部内存 | 8 MB Quad Flash + 8 MB Octal PSRAM，内部堆与PSRAM分别预算 | 16 MB Flash + 16 MB PSRAM；SoC提供250 MHz 8位DDR PSRAM接口，不代表原型默认配置或本项目带宽 |
| GPIO口径 | SoC45；WROOM-1最多36，其中N8R8的35–37被内存占用；DevKit排针表36；扣USB/恢复/启动/RGB后保守24路 | SoC60；WROOM-3为54；CoreBoard J2为29路，Korvo J14为25路含共享信号；实际可规划池见下表，不能直接使用60或54作余额 |
| 解码与文件管理 | WAV/MP3软件处理，microSD由S3唯一读写 | WAV/MP3软件处理，microSD由S31唯一读写；ES8389是PCM ADC/DAC，并非MP3解码器 |

## 计算、内存与存储预算草案

官方`esp_audio_codec` README已列MP3/WAV支持；ESP32-S3R8、44.1 kHz双声道MP3表为28 KB解码堆、8.17% CPU占用，且只统计解码堆，不含任务栈、网络、文件系统、显示或DMA。这是官方测试示例，未披露成套本项目工况；不能外推S31或认定系统只需8.17%的算力。[P7]

下表为建议起始分配和观察条件，不是实测占用，也不是声明的最低配置。两平台按相同软件功能测试，分别记录CPU时间、最长调度间隔和卡写阻塞。

| 资源 | 建议起点或计算 | 限制/验证重点 |
|---|---|---|
| 内部SRAM | 解码、任务栈、I2S/DMA及卡驱动合计先预算96–160 KiB；其中DMA约8–16 KiB、MP3解码28 KB仅为官方线索，最终按实际分配/栈高水位配置 | Wi-Fi/HTTP、系统、界面和索引另计；建议观察最低空闲内部堆及最大连续块，低于64 KiB/32 KiB分别触发检查，这两个数为调试门槛建议，非已批准验收 |
| PCM及外部缓存总额 | 起步192 KiB PCM + 64 KiB压缩预读 + 64 KiB上传/文件缓冲，共320 KiB；外部缓存预算先320–512 KiB。48 kHz、16 bit双声道PCM吞吐192,000 B/s，192 KiB约1.02秒；后续单项比较256/512 KiB PCM，约1.37/2.73秒 | 下两行是总额组成，不重复相加。512 KiB PCM加另两项需至少640 KiB外部缓存；扩大单项时重算总额。内部DMA段接续PSRAM，按低水位/最长阻塞调整，缓存长度不证明覆盖全部写延迟 |
| 压缩预读 | 起步64 KiB PSRAM；后续可单项比较128 KiB。320 kbps时64 KiB约1.64秒文件数据 | CBR计算不能替代VBR峰值；WAV与MP3走不同供数预算，记录低水位 |
| 上传/文件缓冲 | 合计先64 KiB，其中上传接收32 KiB、写块先8–16 KiB，单上传任务起步；音频低水位时减速 | 分块、限速和优先级共同验证；缓冲包含关系按实现核对，不重复记账。只增加缓冲不能消除驱动/文件系统锁长时间持有 |
| 屏幕缓存 | 296×128、1位一帧4,736 B；双色双平面至少9,472 B；双缓冲另翻倍 | 中文字体/解码工作区另算；图片逐张/流式处理，避免把完整曲库图片加载进RAM |
| 内容索引、任务栈与网络 | 索引分批加载，网页静态资源放Flash或SD；实现阶段报告最低余量、失败分配、每任务栈余量 | S3的8 MB和S31的16 MB PSRAM都不代替512 KB内部SRAM；总量足够不证明连续DMA块足够 |
| Flash | S3 8 MiB草案：2个约2.5 MiB应用分区用于更新，约1 MiB网页/资源，约0.25 MiB配置/诊断，其余给启动分区与余量；S31按构建产物再分配 | 只是容量算账，具体地址、OTA启用和字体大小实现时确认；有线恢复不依赖OTA。实际镜像超限时先核查资源放置，不静默换内存配置 |
| 内容存储 | microSD建议先8–32 GB、FAT32做台架；四分钟320 kbps MP3约9.6 MB，44.1 kHz双声道16 bit WAV约42.3 MB | 容量未定稿，歌曲不挤入应用Flash。单文件系统所有者，上传临时文件完成后再发布；断网、满卡和写入断电单独验证 |

平时配置写入内部Flash也可能影响实时任务和PSRAM访问；播放中保存绑定/设置需评估写入时机与内部缓存，不只测试SD上传。PSRAM限制按实际IDF版本核对。[P11]

## GPIO与总线资源草案

### A：S3 N8R8 v1.1

官方排针引出36路GPIO，扣除N8R8内存占用35–37、原生USB19/20、UART恢复43/44、启动脚0/3/45/46、板载RGB38，留下24路保守通用池：`1、2、4–18、21、39–42、47、48`。v1.0 RGB用48，池需改为38；此处不占用外部JTAG的39–42，调试以原生USB为主。若要同时外部JTAG，应另扣4路。[P1][P12]

| 用途 | 主控直连信号数 | 总线/扩展分工 |
|---|---:|---|
| 左右I2S输出 | 3 | BCLK、WS、DOUT；不默认MCLK，若音频选定DAC要求MCLK，再扣1路 |
| microSD，1位SDMMC | 3 | CLK、CMD、D0独立于屏幕SPI；若SPI卡座改4路，或4位SDMMC改6路，分别再扣1/3路 |
| 墨水屏SPI | 5 | SCK、MOSI、CS、DC、BUSY直连；RST可经扩展器。模块若有更多信号须重算 |
| 共享I2C | 2 | NFC、RTC、电源管理与GPIO扩展器；地址和容性负载联合检查，NFC超时不能拖住其他设备 |
| NFC IRQ预留 | 1 | 即使暂用轮询，也保留驱动选择余量；RST经扩展器，SPI/UART版重新分配 |
| 旋钮A/B | 2 | 直连GPIO/计数外设，保留边沿与必要唤醒条件 |
| GPIO扩展器INT | 1 | 按压、播放/暂停、返回及故障输入；可作为待机唤醒来源，完全关机唤醒交电源另核 |
| 灯光数据 | 1 | 直连RMT/SPI时序；5 V灯串电平转换另配 |
| 转盘电机 | 1 | 单向PWM直连；驱动EN/可选DIR经扩展器；若闭环测速另占信号 |
| 电源保持/关断控制 | 1 | 预留给电源方案，不能依赖尚未上电的I2C扩展器才能启动 |
| 电池/负载模拟量预留 | 1 | 限定ADC1可用脚；分压、电量计或其他测量由电源选型，不能直接接电池电压 |
| 原RST占位合计/余额 | **21 / 3** | PN7160 VEN直连先扣1；4位SD另需3，不能在VEN路线仍承诺直接扩展 |

**21 / 3是旧RST占位的条件草案**：RTC共享I2C，NFC使用I2C+IRQ，屏RST、三键及慢速使能可由扩展器承接。PN7160 VEN直连、FAULT及可选盘侧脉冲等尚未包含在该合计，不能直接把余3用于承诺扩展。若沿用DS1302三线RTC，也须新增资源；准确屏/识别/电源器件未定，当前不冻结逐脚接线。音频专项GPIO示例按实际模块联合审阅。

建议扩展器候选为3.3 V、16位、带中断的TCA9535，先核对准确板、地址、上电输入/输出状态及IDF驱动；未列为已批准器件。原约9路慢速需求为三键、屏RST、PN532候选RST、电机EN、音频静音/EN、电源故障与可选在位输入；若PN7160 VEN替代该RST并改直连，则该旧需求释放1扩展口，LIGHT_EN等新增再累计。PN532实际复位脚及总线故障恢复也须按准确模块核对，不能只依赖故障总线上的扩展器。关键使能外部上下拉必须在主控失效/复位时仍有合理状态，不由I2C输出承担高速波形。

**扩展预留仍为候选**：共享3.3 V I2C与受控电源/地可继续评估；UART TX/RX或屏幕SPI的MISO/片选须从扣除VEN及已选新增信号后的余额择一安排，不能沿用旧余3同时承诺。新SPI通常需MISO+CS两路，UART也需两路；新增高速SPI还需独立核对控制器、布线和带宽。

**RC-03A资源增量（2026-10-09，尚待板级复核）：** `PN7160_MINI_I2C`保留为原型候选，首试组合还须与PN532/RC522来源、驱动和实际费用比较。MINI共享现有I2C两线及已计入的NFC IRQ，另需可独立驱动的VEN；为避免I2C被持续拉低时无法通过同总线扩展器复位，建议VEN主控直连、具体GPIO未分配。VEN替代旧RST占位时，S3条件上由21直连/9扩展/余3变成22直连/8扩展/余2；S31已有1路直连RST预算，替代时不重复新增，准确引脚仍重排复核。官方SuperMini样例GPIO8/9/4/5不是DevKitC接线许可；地址`0x28`、上拉/速率与3.3 V逻辑须共同核对。可选在位输入已作为预算占位，是否安装由B真实离座误判证据决定，不能再次无条件加计同一输入。[MINI接口资料](https://www.elechouse.com/docs/pn7160-mini-v1-i2c/datasheet.html)。

**RC-PROT-01 参考工程接入的GPIO检查（2026-10-09）：** 现有草案按共享I2C+NFC IRQ及可能额外直连VEN为PN7160 MINI估算。若选RC522作为低门槛原型，其接口改为SPI SCK/MOSI/MISO/CS与复位，需要单独检查屏幕SPI是否共用SCK/MOSI、MISO引出、片选/复位、电平和总线互斥时延；不能直接继承现有“21路占用、3路空闲”的数字。现有主控音频使用SDMMC与I2S，外部Arduino/WROOM示例GPIO也不能直接复制，固定S3板型、USB恢复、显示/读卡与功耗后才生成真实接线表。额外在位传感器由真实B离座误判证据决定，不在当前自动占用GPIO。参考工程清单见[来源记录](../../references/sources.md#2026-10-09--nfc唱片机与实体音乐播放器参考工程登记)。

### B：S31 Korvo-1 V1.1

板上音频用GPIO2–7、I2C0/1；microSD用20–25及控制39；UART58/59与BOOT61/EN保留。空置J14可共享I2C0/1，按启动脚争议的并集避开GPIO36/38/40/60/61后提供18路候选：`8–19、33–35、43–45`；保留USB Serial/JTAG33/34后为16路。摄像头的46–57不计默认扩展资源；要复用须确认摄像头断开、电源/保护及转接。[P3][P10][P20][P21]

| 外接功能 | 新增直连数 | 预算条件 |
|---|---:|---|
| 墨水屏 | 5 | 独立SPI5信号，RST经扩展器 |
| 旋钮A/B | 2 | 两路直接GPIO |
| NFC IRQ、扩展器INT | 2 | I2C共享0/1，不重复扣GPIO |
| 灯光数据、电机PWM、电源保持 | 3 | 其他使能/按键经同类16位扩展器；电量优先由电源专项给I2C方案 |
| 合计/余额 | **12 / 6** | 如同时保留GPIO33/34的USB Serial/JTAG，余额为4；电池ADC若确需直连，先核ADC引出，不把数字GPIO计作模拟输入 |

这里的余额依赖空置LCD连接器，不等于成品模组的余额；保留USB维护后，比S3草案只多1路直连。第一轮不加LCD子板，不将RGB并行屏/摄像头/USB Host全部启用，再据此宣称首版留有余量。

### 扩展器能补什么

| 后续需求 | 可用方法 | 平台选择影响 |
|---|---|---|
| 更多按键、状态输入、慢速使能、I2C传感器 | I2C扩展器/共享总线，核地址、IRQ与延迟 | S3通常可先保留此类扩展，供电仍须重新预算 |
| 一个UART模块或低吞吐SPI模块 | 分配剩余直接GPIO，核共享SPI时序与MISO释放 | S3有限余额能承担一种组合；S31 Korvo草案余量较多 |
| 第二套I2S、摄像头、并行屏、高速存储 | 对应SoC外设、DMA/内部内存、实际引出及布线 | 单靠普通GPIO扩展器不可实现；有明确需求时优先评估S31准确板/成品模组 |
| 大图片/大量内容缓存 | PSRAM/SD、流式处理与调度 | S31的外部RAM更多，但512 KB内部SRAM约束仍在 |
| 更大功放、电机、灯串、外接USB设备 | 独立驱动、电源轨、限流、热与电池容量 | 与GPIO数量/主频无直接对应，USB Host接口也不证明电源足够 |

## 原型验证与选择条件

本轮没有编译、烧录或实物验证。以下计划用于下一实现对话，不将资料标称/库兼容声明记作通过。

进入S3模块实现前需落实：准确开发板/内存配置与可用出货资料，音频卡座/两路输出模块的准确电平和接口，台架供电与USB外部供电关系，以及用户对板型和解码路线的重要取舍。先完成最小音频、SD与恢复验证，再按各专项已确认接口加入其他模块；完整未来功能清单和S31到货不是S3起步条件。

| 阶段 | 操作与记录 | 进入下一步的建议条件 |
|---|---|---|
| 板型与维护 | 拍摄脱敏板号/模组后缀，读回Flash/PSRAM；固定IDF/组件版本、原理图版本；应用故障后用BOOT/RESET和有线工具恢复 | 准确配置符合候选，下载不依赖应用；USB和外部供电关系明确 |
| 最小声音/存储 | 独立台架供电；D064两条声音路线均完整验证，约1米听距、共用S3/SD/I2S；44.1/48 kHz双声道PCM WAV、MP3 CBR128/320及VBR；左/右测试音 | 两路线分别记录声音与供电证据；各路线迁移S31前后保持同一对单元与音腔。声道/时隙正确、声明格式完整播放；S31 ES8389 TDM尤其确认 |
| D054并发 | AP/STA分别上传新歌，同时播放WAV和MP3；加入墨水屏全刷/局刷、NFC取放、旋钮和灯光/运动 | 建议连续30分钟，欠载0、无不明重启/可听断音；允许上传降速。记录卡阻塞、缓冲低水位、CPU任务时间、内部堆/连续块和PSRAM余量 |

### S3验证到S31成品主线

```mermaid
flowchart LR
```
