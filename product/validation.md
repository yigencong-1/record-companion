# 整机验收与证据索引

当前只有规划、公开资料核查和概念图。尚无固件编译/烧录、实物接线、识别、音质、充电、温升或续航的通过结果。T编号是建议验收计划；V编号保留历史产物的追溯，不代表整机已通过测试。

## 每轮验证记录格式

| 记录项 | 必须说明的内容 |
|---|---|
| 日期、目标与范围 | 所处阶段、对应F/T编号及本轮要验证的问题 |
| 可复现条件 | 准确板卡/模块/结构版本、接线与供电、固件提交、工具和操作 |
| 结果与证据 | 预期行为、实际观察、必要数据/图片及证据文件位置 |
| 结论与下一步 | 已通过项、尚未验证项、失败现象和受影响的复测范围 |

概念图、模拟、静态检查、编译、烧录、总线观测、实物功能和使用体验分别标明。公开记录保存准确技术条件与脱敏结果；个人库存、订单、私人素材、本机路径和会话过程不写入本文件。实际验证文件随对应工程保存，这里引用版本和结论，不重复整份日志。

### T02原型补充：RC-03A可靠离座测量建议（未执行）

- 两读卡天线分别检验8个已绑定电子身份与1个未绑定身份；若取到小圆标签样品，按20/25/30 mm完整外形、0/1/2/3 mm新增隔距、中心/偏心/倾斜、正反面分阶段扫描，记录“读卡线圈到标签线圈”的总间距。
- 使用独立物理动作真值（同步视频或独立夹具传感器）对齐读卡/NCI时间戳和播放器事件，分别报告放片身份确认、B实际取走到停止、快换片的p50/p95/最大延迟，不以平均数掩盖最差情形。沿用身份≤500ms、B离座退出≤500ms、音频开始≤1s作为原型建议目标。
- B持续在位建议不少于30分钟，并注入50/100/200ms短暂失联、重启读卡器、邻片靠近、金属扣和电机干扰；记录误退出/错身份/重复触发。最终建议覆盖八张卡各20次共160次操作，0错误为原型筛查而非长期可靠性统计结论。
- 若纯NFC反复误判或无法区分读卡器故障与真实离座，T02不记通过，开展“独立在位检测”方案对照；改变传感器、天线/结构或供电后复测受影响场景。附各模块/标签批次、SDK/驱动版本、供电与参数及未通过样例，不将资料页最大读取距离当作本项目性能证据。

以下是**行为验证用例**，不是固件测试结果。与T02的物理取放可靠性不同，逻辑层测试可用确定性事件注入；“建议”案例应先经用户确认再进入正式产品验收基线。

| L20 | B/C旧会话暂停或已退出→旧EOF回调 | 不无意续播或切歌；建议异步会话门禁 |
| L21 | 修改当前在位卡的映射→保存成功 | 不伪造新放置；推荐下一次真放入或显式操作才生效，待确认 |
| L22 | B/C主动STOP与MODE_EXIT / C断电重启 / 新行为启动后失败 | U3–U5尚未确认；只记录候选期望，不宣称已通过 |

**验证准则**：每条案例保留初始在位与会话状态、命令来源、事件序号、期望/实际模式、音频/队列状态及迟到事件处理。用户未确认的U1–U5作为待审阅项，真实硬件验收还须完成T02卡座/读区/误判/时延测试。任何“测试通过”只针对实际执行过的脚本/设备版本，不根据文档存在自动判PASS。
