# 整机规划

本目录负责产品范围、跨功能目标和整机验收。单功能的参数与试验方案放在 [`features/`](../features/)；实际工程分别放在固件、硬件、网页和结构目录。

ABC行为、内容管理与硬件规划在此维护共同范围。现行规则以[决策记录](decisions.md)、[共享接口](interfaces.md)及[验收计划](validation.md)为准；旧统一取走暂停和固定旋钮/两键概念已被修订。跨B/C替换及全坏停止后的显式恢复已按D089–D090确认，具体器件、控件数量和实现阈值依专项验证收敛。

## 已确认产品

本体是一套通用本地音乐播放器、唱片桌搭和唱片挂件。它可以离线播放本地音乐，以前置屏与灯光提供日常桌搭体验，评估左右扬声器，并希望实现唱片转动；无唱片时仍能从本体或网页播放。大唱片确定平放，小挂件比较浅座与无需扣紧的插槽。挂件也可挂在书包上，采用无电池的NFC或类似电磁感应技术，按独立身份编号关联内容；具体器件、编号与内容绑定的保存方式仍待评审。

首批共八张以圆形为基础的卡：邓紫棋、汪苏泷各一张，编号1–5的通用小唱片各一张，以及编号0的生日卡一张。按D065，歌手卡图案后续由用户设计，通用卡不使用明显大数字；生日卡采用近圆形蛋糕轮廓，背面仅“生日快乐”。不同卡片可以采用不同材质，多个完整外壳方案并行比较；两张歌手卡和生日卡重点关注外观与耐用性。生日仍只有一张卡和一个菜单入口。

阶段主控依D063确定为S3模块验证、S31成品主线；准确板型、内存和成品芯片或模组配置尚未冻结。声音依D064并行验证音质与性价比两条路线，主要听距约1米，最终音频器件与费用由可比较证据收敛。

## 当前操作规则

本节保留早期决定的上下文；取走动作、播放接管及控件映射以跨分支联合整合后的规格为实现依据，不再以本节旧条目冻结硬件。

- 唱片与本体、网页是并列播放入口。
- 按D066–D069，A单曲点播取走继续；B驻留模式确认取走后退出并停止清空其播放任务；C锁存模式取走后继续；B/C单曲/歌单循环。持续在位不重复触发。
- 有效新A或本体/网页主动选择其他歌曲时，先完整退出原B/C再播放；音量调整、暂停及模式内切歌不退出。手动退出后需真正取走再放回才能自动重启B/C。
- NFC标签仅提供独立电子数字身份；本体根据身份决定ABC类型和目标。
- 开机已有唱片先识别，等待显式启动；正常运行新放片才自动执行ABC。启动按键尚待选择。
- 无唱片时，本体或网页仍可开始播放。未绑定或内容缺失时应给出状态反馈，具体错误呈现待细化。
- 日常显示采用时间/日期、播放器状态、事件页面和静态图片切换，离线可用；AI留到后续扩展。
- 本体离线操作覆盖基本全部首版功能；网页提供另一个控制和内容管理入口。
- 可按压旋钮与播放/暂停、返回键仅为当前交互概念；实体控件数量、种类和功能均可继续调整。
- 网页上传新歌曲时保持当前音乐播放，允许上传变慢；能否无断音须在原型并发条件下验证。

### RC-06内容管理行为（D076–D081已确认）

建议稳定区分电子UID、逻辑卡、绑定、歌曲Track ID、歌单Playlist ID和模式目标；具体落盘格式仍待实现。D076–D081已确认：被卡/歌单/播放引用的歌曲须先解除引用才能删除；B/C歌单修改下次进入生效；在位重绑只保存，允许显式执行新绑定；STOP后显式PLAY从当前选曲开头重播（STOP中NEXT按D082更新选曲但不发声）；运行中坏歌跳过、全不可播则停音频但模式继续；本体可离线进行基础歌单编辑，复杂批量操作主要用无外网要求的设备AP网页。实体按键数量和菜单层级未冻结。详见[共享接口](interfaces.md#rc-06--曲库歌单绑定与统一控制的数据契约2026-10-09提案)和[实施规划](plan.md#rc-06--曲库歌单身份绑定与本体网页统一控制2026-10-09产品行为已确认)。

### RC-07新增确定规则（D082–D085）

已确认：B/C的STOP态模式内切歌只更新选曲且保持静音；仍被唱片、生日入口或活动B/C引用的歌单禁止直接删除，删除歌单不删除歌曲文件；文件经完整修复校验与成功发布后自动恢复当前会话坏曲的可播资格，下次正常轮到再试，全不可播已停音频时不自动发声；本体/网页同配置以**最后成功保存者覆盖**，网络同一请求重试不得重复提交。活动模式保持原绑定/歌单快照，硬件按键与具体事务实现仍待审阅。

### RC-08软件交付与硬件待测

软件当前主入口为[协作者控制器整合版](../firmware/simulator/README.md)，已融入D093–D095、首次失败/故障保护及异步音频、媒体版本和JSON进程恢复回归，结果见[V023](validation.md#v0232026-10-14-软件主版本实质整合)。[0.2.2-batch2](../firmware/simulations/playback-controller/README.md)保留47项补充证据，涵盖SQLite、合成WAV发布与旧文件句柄等实验。它们均为PC范围；SD掉电、真实适配器、MP3、页面与实物性能仍独立验收。

### 本轮已确认的三条操作路径

| 路径 | 逐步走查 | 已实现控制规则与待验边界 |
|---|---|---|
| 普通独立播放开机恢复 | 选中歌曲/歌单并播放；正常关机；重启显示此前选择但保持静音；用户明确播放，从所选曲目0:00开始 | 不恢复旧播放位置或旧B/C；开机在位唱片仍等待明确启动。记忆写入时点与异常断电恢复由存储专项落实，目标已删除/损坏时需明确反馈，不静默播替代内容 |
| 登记或重绑唱片 | 先进入绑定页；再放片读取身份；编辑类型/目标并预览；保存后显示实际结果，取消保留原绑定 | 放片、保存及同片持续在位均不自动触发音乐。实际B离座正常退出，故障保护仍有效；退出页面不补发自动放片。已在位才进页面的操作引导仍待界面走查 |
| 暂停后选择下一首 | 播放中暂停；一次或多次NEXT选择下一首，保持暂停；明确PLAY从最新选曲0:00开始 | 旧曲回调不出声、不改选曲；不切歌直接恢复仍接原位置；STOP后NEXT静音规则保持不变 |

首先核对每条流程在无手机、无外网时是否可完成，再比较控件和页面候选。跨B/C及D093–D095已在软件主版本落实并回归，见V023；这些PC控制接口不等于完整菜单、屏幕或网页已经实现。事件、生日、低电等其余体验仍待审阅，实际换片与界面性能另做硬件验证。

## 跨功能目标

音质不能因为追求小体量而被静默牺牲。扬声器、音腔、功放、供电、机械噪声和成品材料要一起试听；整体外形尽量紧凑，但厘米数由实物模块和装配路径反推。电池支持Type-C边充边用，续航目标为尽量长，必须通过平均/峰值功耗和完整放电测试确定。所有候选器件先比较性能、价格、尺寸、功耗、软件与供货证据，再形成推荐。
